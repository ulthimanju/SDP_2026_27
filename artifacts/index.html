Mathematical Model

3-Tier Dynamic Integrity Lattice

Conventional binary taint models (tainted vs. untainted) suffer from utility collapse. AgentTaint introduces a calibrated 3-tier lattice model: TRUSTED < SANITIZED < UNTRUSTED.

TIER 1 TRUSTED (High Integrity)

User & System Space

  • Authenticated user commands
  • Pre-configured system prompts & tool schemas
  • Authorized developer-approved configurations
Permitted Sinks: State-changing APIs (Send Email, Delete DB, Shell Execute, File Write)
⬇️ Taint Propagation
⬆️ Schema Declassification
TIER 2 SANITIZED (Declassified Facts)

Schema-Locked Primitives

  • Typed entities extracted via regex or Pydantic schemas
  • Dates, monetary figures, tracking numbers, IDs
  • Free of imperative natural language instructions
Permitted Sinks: Read tools, queries, vetted parameters (with policy constraints)
⬇️ Ingestion from Outside
TIER 3 UNTRUSTED (Low Integrity)

External Environment Data

  • Web scraping payloads, untrusted emails & attachments
  • Customer reviews, public documents, database records
  • Potential attack vector for Indirect Prompt Injections
Permitted Sinks: Pure read-only reflection, summarization memory. Forbidden from state-changing sinks!
Deep Dive Subsystems

The Five Core Pillars of AgentTaint

Designed to operate as a zero-overhead, model-agnostic middleware between standard LLM orchestrators and tool environments.

01

Dynamic Taint Tagging

Every token flowing into the agent runtime is annotated with provenance metadata. Tokens inherit taint tags through multi-hop transformations, distinguishing pure user directives from untrusted third-party inputs.

Token-level metadata Zero LLM fine-tuning Cross-turn persistence
02

Provenance DAG Tracker

Maintains a real-time Directed Acyclic Graph (DAG) charting causal dependencies. If an argument for delete_record(id) derived its parameter value from an untrusted webpage, the DAG exposes the contaminated dependency path instantly.

Causal Dependency Tracking Embedding Similarity Traceable Audit Trail
03

Counterfactual CFI Probe

Prevents implicit control-flow hijacking where attacker text causes the agent to invoke dangerous tools without contaminating argument strings. Probes whether the tool invocation logically stems from original user goals.

Control-Flow Integrity Anomalous Tool Detection Goal-Conditioned Verification
04

Schema-Locked Declassification

Overcomes the historic "over-tainting" barrier of classical Information Flow Control. Agents can parse structured facts (e.g. tracking code) into sanitized types without inheriting embedded prompt injection attacks.

Typed Pydantic Schemas Imperative Command Stripping > 92% Benign Utility
05

Capability Policy Engine

A deterministic reference monitor executing in Python. It parses declarative YAML capability matrices, matching tool names, sink risk categories, and parameter provenance against mathematical access policies.

Deterministic Code Checks Non-Jailbreakable Human-in-the-Loop Hooks

Policy Configuration

Declarative YAML Capability DSL

Security engineers define deterministic capability boundaries without writing complex glue code. Policies are strictly enforced by the reference monitor.

version: "1.0"
agent_scope: "CustomerSupportAssistant"

# Definition of Tool Sinks and Permitted Information Tiers
sinks:
  - tool_name: "send_email"
    risk_level: "HIGH"
    allowed_argument_taint:
      recipient: ["TRUSTED"]
      subject: ["TRUSTED", "SANITIZED"]
      body: ["TRUSTED", "SANITIZED"]
    action_on_violation: "BLOCK"
    cfi_intent_check: true

  - tool_name: "sql_execute"
    risk_level: "CRITICAL"
    allowed_argument_taint:
      query: ["TRUSTED"]
    action_on_violation: "BLOCK"

  - tool_name: "save_note"
    risk_level: "LOW"
    allowed_argument_taint:
      note_text: ["TRUSTED", "SANITIZED", "UNTRUSTED"]
    action_on_violation: "ALLOW"

declassification_schemas:
  - schema_id: "flight_booking_schema"
    fields:
      - name: "flight_number"
        type: "regex"
        pattern: "^[A-Z]{2,3}[0-9]{3,4}$"
      - name: "departure_date"
        type: "datetime"
